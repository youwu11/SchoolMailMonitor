Phase 2 — Create Kids Email Monitor

Create a scheduled task named Kids Email Monitor, running hourly in Australia/Sydney.

Initial Setup: Before creation, confirm children’s names, preferred names, schools, classes, attendance days and extracurricular activities. Keep family configuration separate from operational state.

Goal: Monitor connected Outlook for new or updated child-related emails, including schools, childcare, extracurriculars, birthdays, playdates and medical appointments. Ignore marketing.

Processing & Storage: Read accessible emails, attachments and linked notices, using Cloud Browser when supported. Extract and save meaningful child-related updates, events, preparations and actions to kids_email_state.json. Preserve source links and updates. Reminder delivery is handled separately.

Reporting: Summarise meaningful updates on each child’s school life, learning, activities, progress and wellbeing in natural, concise Simplified Chinese, like a thoughtful personal assistant for a busy mum. Highlight key dates, actions and preparations, include source links, flag urgent changes promptly, and avoid speculation, trivial updates or duplicate notifications.

Reliability: Use a 2-hour email overlap, stable IDs and change detection to deduplicate and process updates. Maintain checkpoints and retry failed processing without losing valid state. Advance checkpoints only after verified persistence. Keep records compact; never store full email bodies. Verify file access and report failures or unverified cross-run persistence.

Safety: Write operational data only to kids_email_state.json Never modify other tasks or this task description, or store operational history in the task prompt. 

Setup & Verification: Confirm required access, initialise state files only if absent and writable, then create only Kids Email Monitor. Verify its hourly Sydney schedule, complete instructions and available file persistence; report unsupported capabilities.
